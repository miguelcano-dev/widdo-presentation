Flujo Completo de Prueba

Sigue estos pasos para verificar que todo el ciclo de pago funciona end-to-end.

01
Iniciar sesión en Widdo
Ve a app.widdo.co y entra con un club expirado o crea uno nuevo.
URL: https://app.widdo.co/login
02
Ir a la página de suscripción
Desde el menú lateral, click en "Suscripción" o navega directamente a la URL.
URL: https://app.widdo.co/home/subscription
03
Seleccionar plan
Elige uno de los 3 planes (Básico, Pro, Enterprise). Recomendado: Básico mensual porque es el monto más pequeño y más rápido de verificar.
04
Seleccionar pasarela
Aparecerá el selector con los gateways disponibles según tu país. En test mode solo verás Stripe (hasta que actives Wompi/dLocal).
05
Click "Suscribirse"
El sistema te redirige a checkout.stripe.com con el precio correcto según tu país.
06
Rellenar tarjeta de prueba
Usa alguna de las tarjetas del punto 3. Email/nombre/dirección pueden ser cualquier cosa.
Tarjeta:  4000 0566 5566 5556
CVV:      123
Fecha:    12/29
Nombre:   Test Widdo
Email:    test@widdo.co
ZIP:      110111
07
Verificar activación automática
Stripe te redirige de vuelta a Widdo. En menos de 5 segundos, el webhook debe activar la suscripción. Ve al dashboard y verifica que puedes crear jugadores de nuevo.

Verificar en BD (opcional)

Configurar Wompi (Colombia)

Wompi es la mejor opción para Colombia porque acepta PSE, Nequi, Bancolombia y Daviplata — que usa el 80% de la gente en Colombia.

Wompi
Colombia · PSE · Nequi · Bancolombia · Daviplata · Tarjetas
Pendiente Keys

Paso 1 · Crear cuenta en Wompi

01
Ve a comercios.wompi.co y crea una cuenta. Solo necesitas tu cédula. No piden datos bancarios para sandbox.

Paso 2 · Obtener las 4 llaves API

02
Dentro del dashboard de Wompi, ve a Desarrolladores → Llaves API y copia las 4 credenciales de Sandbox: 
pub_test_xxxxxxxxxxxxxxxx       (Public Key)
prv_test_xxxxxxxxxxxxxxxx       (Private Key)
integridad_test_xxxxxxxxx       (Integrity Secret)
eventos_test_xxxxxxxxxxxxx      (Events Secret)

Paso 3 · Configurar Webhook en Wompi

03
En el dashboard de Wompi, ve a Desarrolladores → Webhooks → Agregar Endpoint: 
URL:       https://api.widdo.co/api/webhooks/wompi/CO
Eventos:   transaction.updated
           nequi_token.updated
           bancolombia_transfer_token.updated

Paso 4 · Activar en Widdo

04
Pásame las 4 keys o ejecuta este comando en el servidor de producción reemplazando los valores: 
Producción
ssh root@167.71.88.31
cd /var/www/widdo
php artisan tinker --execute="
DB::table('bas_country_payment_config')
  ->where('country_id', 22)
  ->where('gateway_id', 1)
  ->update([
    'public_key' => 'pub_test_XXXXX',
    'private_key' => 'prv_test_XXXXX',
    'webhook_secret' => 'eventos_test_XXXXX',
    'extra_credentials' => json_encode([
      'integrity_secret' => 'integridad_test_XXXXX'
    ]),
    'is_active' => 1,
  ]);
echo 'Wompi activado ✓';
"
php artisan cache:clear

Paso 5 · Probar Wompi

05
Ve a /home/subscription desde un club colombiano. Ahora verás 2 gateways: Stripe y Wompi. Elige Wompi, selecciona PSE y prueba con el banco de pruebas que proporciona Wompi.

Configurar dLocal (LATAM Completo)

dLocal cubre los países donde Stripe no tiene métodos locales fuertes: Argentina (Rapipago), Brasil (PIX, Boleto), Perú, Chile, Ecuador y más.

dLocal
AR · BR · CL · CO · EC · MX · PE · UY · DO · GT · PA · CR · BO
Pendiente Keys

Paso 1 · Crear cuenta en dLocal

01
Ve a dlocal.com y aplica para una cuenta merchant. Importante: dLocal requiere documentos formales de tu C Corp (EIN, incorporación, bank statement de Mercury). El proceso de aprobación toma 3-7 días hábiles.

Paso 2 · Obtener credenciales de Sandbox

02
Una vez aprobada la cuenta, ve a Settings → Integration → Credentials y selecciona Sandbox: 
x_login:       XXXXXXXXXXXXX    (API Login)
x_trans_key:   XXXXXXXXXXXXX    (Trans Key)
secret_key:    XXXXXXXXXXXXX    (HMAC Secret)

Paso 3 · Configurar Webhook en dLocal

03
En dLocal Dashboard, ve a Settings → Webhooks: 
URL:       https://api.widdo.co/api/webhooks/dlocal
Eventos:   payment.created
           payment.updated
           payment.refunded

Paso 4 · Activar por país

04
dLocal se activa por país. Por ejemplo, para habilitarlo en Argentina: 
Producción
ssh root@167.71.88.31
cd /var/www/widdo
php artisan tinker --execute="
DB::table('bas_country_payment_config')->insert([
  'country_id' => 6,  // 6=AR, 33=BR, 65=MX, 22=CO, etc
  'gateway_id' => 8,  // dLocal
  'is_default' => true,
  'is_active' => true,
  'environment' => 'sandbox',
  'public_key' => 'XLOGIN',
  'private_key' => 'XTRANSKEY',
  'webhook_secret' => null,
  'extra_credentials' => json_encode([
    'secret_key' => 'SECRETKEY'
  ]),
  'enabled_methods' => json_encode([
    'card', 'rapipago', 'pagofacil'
  ]),
  'created_at' => now(),
  'updated_at' => now(),
]);
echo 'dLocal AR activado ✓';

07

Pasar Stripe a Live Mode

Cuando tengas tu primer cliente real pagando, necesitas cambiar de test mode a live mode.

⚠
No pases a live mode hasta que: (1) hayas probado TODO el flujo en test, (2) tengas al menos 1 cliente confirmado, (3) tu C Corp esté verificada en Stripe, (4) Mercury esté conectado para recibir payouts.

Checklist para activar Live Mode

  • Activar Live Mode en Stripe Dashboard (verifica C Corp)
  • Copiar nuevas keys live: pk_live_... y sk_live_...
  • Crear webhook LIVE con los mismos 8 eventos apuntando a api.widdo.co/api/webhooks/stripe
  • Copiar el nuevo whsec_... del webhook live
  • Recrear productos y precios en Live Mode (los de test mode NO funcionan en live)
  • Actualizar stripe_product_id y stripe_price_id en BD con los IDs live
  • Actualizar .env producción con las nuevas keys live
  • Actualizar bas_country_payment_config con environment = 'production'
  • Ejecutar php artisan config:clear && php artisan config:cache
  • Hacer una prueba con tarjeta real (puede ser tu propia tarjeta, cobrarte $1 y reembolsarlo)
!
En live mode NO uses tarjetas de prueba. Solo funcionan tarjetas reales. Si intentas 4242... en live mode, Stripe la rechaza.

Troubleshooting

Problema: "Los pagos no están habilitados para tu país"

Causa: El club no tiene ciudad asignada o el país no tiene payments_enabled = 1 o no hay gateway configurado.

Solución:

php artisan tinker --execute="
// Verificar que el club tiene ciudad
\$club = DB::table('pla_club_teams')->find([CLUB_ID]);
echo 'city_id: ' . \$club->city_id . PHP_EOL;

// Verificar que el país tiene pagos habilitados
\$countryId = DB::table('bas_cities as c')
  ->join('bas_states as s', 'c.state_id', '=', 's.id')
  ->where('c.id', \$club->city_id)
  ->value('s.country_id');
echo 'country_id: ' . \$countryId . PHP_EOL;

\$enabled = DB::table('bas_countries')
  ->where('id', \$countryId)
  ->value('payments_enabled');
echo 'payments_enabled: ' . \$enabled . PHP_EOL;

// Verificar gateway configurado
\$gw = DB::table('bas_country_payment_config')
  ->where('country_id', \$countryId)
  ->where('is_active', true)
  ->first();
print_r(\$gw);
"

Problema: Webhook no llega después de pagar

Causa: Webhook mal configurado en Stripe Dashboard, secret incorrecto, o firewall bloqueando.

Solución:

# Ver eventos recientes del webhook en Stripe Dashboard
https://dashboard.stripe.com/test/webhooks

# Ver logs del servidor
ssh root@167.71.88.31
tail -f /var/www/widdo/storage/logs/laravel.log | grep -i stripe

# Verificar que el secret coincide
cd /var/www/widdo
grep STRIPE_WEBHOOK_SECRET .env

Problema: Paywall no aparece después del trial

Causa: El middleware no está aplicado a las rutas o la suscripción sigue activa.

Solución:

# Forzar expiración de trial en un club
php artisan tinker --execute="
DB::table('pla_club_teams_subscriptions')
  ->where('club_id', [CLUB_ID])
  ->update([
    'status' => 'expired',
    'current_period_end' => now()->subDay(),
    'trial_ends_at' => now()->subDay(),
  ]);
"

Problema: Tarjeta de prueba "rechazada"

Causa: Estás usando keys live en vez de test, o la tarjeta es una de las de error intencional.

Solución: Verifica que las keys empiezan con sk_test_ / pk_test_. Usa 4000 0566 5566 5556 o 4242 4242 4242 4242 que siempre aprueban.
