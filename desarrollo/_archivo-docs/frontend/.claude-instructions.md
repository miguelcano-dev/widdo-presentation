# Claude Instructions - Widdo Frontend

## Project Overview
SaaS sports club management system built with React 18 + Vite. Multi-tenant with 6-role RBAC system.

## Essential Commands

```bash
# Development
npm run dev              # Start dev server (http://localhost:5173)
npm run build            # Production build
npm run preview          # Preview production build
npm run lint             # ESLint check

# Testing
npm run test:e2e         # Run all E2E tests
npm run test:e2e:ui      # Interactive test UI
npm run test:e2e:owner   # Owner flow tests
npm run test:e2e:trainer # Trainer flow tests
```

## Project Conventions

### File Naming
- **Components:** PascalCase (`PlayerForm.jsx`)
- **Hooks:** camelCase with `use` prefix (`usePlayerData.js`)
- **Services:** camelCase with `Service` suffix (`playerService.js`)
- **Pages:** PascalCase with `Page` suffix (`DashboardPage.jsx`)

### Component Structure
```jsx
// 1. Imports (React, external, internal)
// 2. Component definition
// 3. State declarations (useState, useReducer)
// 4. Hooks (useAuth, useQuery, etc.)
// 5. Handlers/functions
// 6. Effects (useEffect)
// 7. Render
// 8. Export
```

### Imports
Use `@/` alias for src directory:
```jsx
import { Button } from '@/components/ui/button';
import { useAuth } from '@/hooks/context/useAuth';
```

## RBAC System (6 Roles)

| Role | Level | Access |
|------|-------|--------|
| Super Admin | 100 | System-wide |
| Owner | 80 | Full club + Finances |
| Accountant | 60 | Financial modules only |
| Trainer | 40 | Sessions + Attendance |
| Parent | 20 | Children's data |
| Player | 10 | Own data only |

### Adding Protected Routes
```jsx
// In App.jsx
<Route
  path="new-route"
  element={
    <PrivateRoute>
      <AdminRouteGuard> {/* or FinancialRouteGuard, etc. */}
        <NewPage />
      </AdminRouteGuard>
    </PrivateRoute>
  }
/>
```

## Important Patterns

### Date Handling
**ALWAYS use dateUtils.js** - JavaScript Date has timezone issues:
```jsx
import { formatDisplayDate, parseDateString } from '@/helpers/dateUtils';

// Correct
const date = parseDateString('2024-01-13');

// Incorrect - may lose a day
const date = new Date('2024-01-13');
```

### Currency Inputs
Format only on blur, not while typing:
```jsx
const [focused, setFocused] = useState(false);
<Input
  value={focused ? rawAmount : formatCurrency(rawAmount)}
  onFocus={() => setFocused(true)}
  onBlur={() => setFocused(false)}
/>
```

### Loading States
Use unified LoadingSpinner:
```jsx
import LoadingSpinner from '@/components/loading/LoadingSpinner';

// Page loading
<LoadingSpinner variant="centered" size="lg" />

// Inline loading
<LoadingSpinner variant="inline" size="sm" />
```

### API Calls
Use React Query hooks or services, never direct axios:
```jsx
// Good
const { data, isLoading } = usePlayerData(playerId);

// Good
const players = await apiService.get('/players');

// Avoid
const players = await axios.get('/api/players');
```

### Form Handling
Always use React Hook Form + Zod:
```jsx
const { control, handleSubmit } = useForm({
  resolver: zodResolver(schema),
  defaultValues: {},
});
```

## Do's and Don'ts

### DO
- Use existing components from `@/components/ui/`
- Use guards for route protection
- Use React Query for data fetching
- Use `data-testid` attributes for E2E tests
- Handle loading and error states

### DON'T
- Create new files when editing existing ones works
- Use `<input type="date" />` - use FormDateInput
- Format currency while user is typing
- Use console.log - use SecureLogger
- Combine Radix Checkbox with ScrollArea in lists

## Testing Checklist
When adding features:
1. Add `data-testid` to interactive elements
2. Verify guards block unauthorized access
3. Test mobile responsiveness
4. Check dark mode compatibility
5. Validate form error states
