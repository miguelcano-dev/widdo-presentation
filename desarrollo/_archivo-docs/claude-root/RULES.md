# 📜 REGLAS DE DESARROLLO - WIDDO V1

## 🚫 PROHIBICIONES ABSOLUTAS

### 1. Referencias a Herramientas de IA
**NUNCA incluir en código, commits o comentarios:**
- ❌ "Generated by Claude"
- ❌ "AI-generated"
- ❌ "Co-Authored-By: Claude"
- ❌ Referencias a cualquier asistente de IA
- ❌ Menciones de "automated", "auto-generated" en contexto de IA

**Mantener**: Código profesional estándar sin referencias externas.

---

### 2. Commits No Profesionales
**NUNCA hacer commits con:**
- ❌ Mensajes vagos: "fix stuff", "updates", "changes"
- ❌ TODO críticos sin resolver
- ❌ console.log olvidados
- ❌ Código comentado en bloques grandes
- ❌ Archivos de configuración locales (.env con valores reales)

---

## ✅ ESTÁNDARES OBLIGATORIOS

### 1. Estructura de Branches
```
main (producción)
  ↓
develop (integración)
  ↓
  ├── feature/fase-1-seguridad-critica
  ├── feature/fase-2-performance-ux
  ├── feature/fase-3-testing-critico
  └── feature/fase-4-refinamiento
```

**Regla**: Una rama por FASE completa, NO por tarea individual.

---

### 2. Convención de Commits
**Formato obligatorio**: `tipo: descripción clara`

**Tipos válidos**:
- `feat:` Nueva funcionalidad
- `fix:` Corrección de bug
- `refactor:` Refactorización sin cambio funcional
- `perf:` Mejora de performance
- `test:` Tests
- `docs:` Documentación
- `style:` Formato (no afecta lógica)
- `chore:` Mantenimiento

**Buenos ejemplos**:
```bash
✅ fix: Sanitize HTML content to prevent XSS attacks
✅ feat: Add error boundary to dashboard pages
✅ refactor: Memoize context values to reduce re-renders
✅ test: Add authentication flow tests with Playwright
```

**Malos ejemplos**:
```bash
❌ "fixed things"
❌ "updates"
❌ "wip"
❌ "asdf"
```

---

### 3. Workflow de Desarrollo

#### Al Iniciar una Fase:
```bash
git checkout develop
git pull origin develop
git checkout -b feature/fase-X-nombre
```

#### Durante Desarrollo:
```bash
# Commits frecuentes (cada hora o feature completa)
git add .
git commit -m "tipo: descripción"
git push origin feature/fase-X-nombre
```

#### Al Completar Fase:
```bash
# Verificar checklist pre-merge
git status
git push origin feature/fase-X-nombre
# Crear PR en GitHub/GitLab
```

#### Después del Merge:
```bash
git checkout develop
git pull origin develop
git branch -d feature/fase-X-nombre
```

---

### 4. Checklist Pre-Commit (Cada Commit)

Antes de hacer `git commit`:
- [ ] Código funciona sin errores
- [ ] No hay console.log olvidados
- [ ] No hay TODOs críticos sin resolver
- [ ] Código formateado (Prettier automático)
- [ ] Nombres de variables descriptivos

---

### 5. Checklist Pre-Push (Antes de Push)

Antes de hacer `git push`:
- [ ] Frontend compila sin warnings críticos
- [ ] Backend no tiene errores de sintaxis
- [ ] Tests críticos pasan (si los hay)
- [ ] No se incluyen archivos de configuración local

---

### 6. Checklist Pre-PR (Pull Request)

Antes de crear Pull Request:
- [ ] Todos los commits tienen mensajes claros
- [ ] Código está actualizado con develop (rebase si necesario)
- [ ] README actualizado si hay cambios en setup
- [ ] PROGRESS.md actualizado con tareas completadas
- [ ] No hay código comentado sin justificación
- [ ] No hay referencias a herramientas de IA
- [ ] Tests pasan (si los hay en esa fase)

## 🔒 SEGURIDAD - REGLAS CRÍTICAS

### 1. XSS Prevention
```jsx
// ✅ SIEMPRE sanitizar HTML
import DOMPurify from 'dompurify'
<div dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(html) }} />

// ❌ NUNCA directamente
<div dangerouslySetInnerHTML={{ __html: html }} />
```

### 2. Validación Doble
```
FRONTEND: Zod validation → UX mejorada
BACKEND: Form Requests → Seguridad real
```

### 3. Autorización
```php
// ✅ SIEMPRE usar policies
$this->authorize('view', $player);

// ❌ NUNCA lógica directa
if ($user->id !== $player->user_id) { // ❌
    abort(403);
}
```

### 4. Secrets
```bash
# ✅ En .env
DB_PASSWORD=secreto

# ❌ NUNCA en código
$password = "mipassword123"; // ❌
```

## 📊 PERFORMANCE - REGLAS

### 1. React Query
```jsx
// ✅ Usar staleTime y cacheTime apropiados
useQuery(['players'], fetchPlayers, {
  staleTime: 5 * 60 * 1000, // 5 minutos
  cacheTime: 10 * 60 * 1000, // 10 minutos
})

// ❌ Queries sin configuración
useQuery(['players'], fetchPlayers) // ❌ Refetch en cada mount
```

### 2. Memoization
```jsx
// ✅ Memoizar valores computados
const expensiveValue = useMemo(() =>
  computeExpensive(data),
  [data]
)

// ✅ Memoizar callbacks
const handleClick = useCallback(() => {
  doSomething(id)
}, [id])
```

### 3. Images
```jsx
// ✅ SIEMPRE lazy loading
<img src={photo} loading="lazy" alt="descriptivo" />
```

## ⚠️ ERRORES COMUNES A EVITAR

### 1. Git
```bash

git add src/pages/BlogPage.jsx

git add src/utils/sanitize.js

```

### 2. Merge Conflicts
```bash
# ❌ Force push a develop/main
git push --force origin develop  # ❌ NUNCA

# ✅ Force push solo a tu feature branch
git push --force-with-lease origin feature/fase-X
```

### 3. Imports
```jsx
// ❌ Imports relativos complejos
import { helper } from '../../../utils/helper'

// ✅ Path aliases
import { helper } from '@/utils/helper'
```
